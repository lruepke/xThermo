    Installation

    xThermo is a C++ library with Python bindings. Python users install the Python package xthermo with pip; C++ users build and install the library with CMake.

    Python package

    From the repository root, in any Python ≥ 3.10 environment (venv, conda, …):

    pip install .                 # or: pip install ".[plotting]" to add numpy and matplotlib

    pip builds the extension modules with CMake and SWIG (both taken from PyPI if they are not installed) and links a GSL that it builds from the official source archive (checksum-verified). Only a C/C++ compiler and make are needed.

    import xthermo
from xthermo import H2ONaCl

sw = H2ONaCl.cH2ONaCl("IAPS84")
print(sw.UpdateState_TPX(573.15, 300e5, 0.1).Rho)

    The former package name still works: from xThermal import H2ONaCl gives the same modules.

    The rest of this page builds the C++ library (and the Python modules for development) with CMake.

    Dependencies

    Dependency Required Notes
    C++ compiler (gcc ≥ 11 or Apple clang) yes the code is compiled as C++11
    CMake ≥ 3.18 yes
    GSL yes any GSL 2.x; from the system, or built from source by CMake (see step 1)
    SWIG ≥ 4 for the Python modules macOS: brew install swig; Linux: apt install swig
    Python ≥ 3.10 with development headers for the Python modules any environment
    PROST 4.1 bundled IAPS-84 water backend; compiled automatically

    1. GSL

    Install GSL with your package manager:

    brew install gsl              # macOS
sudo apt install libgsl-dev   # Debian/Ubuntu
conda install -c conda-forge gsl

    CMake finds it automatically; for a GSL in a non-standard location add -DGSL_ROOT_DIR=<prefix> in step 3. Without a system GSL, add -DXTHERMO_BUNDLED_GSL=ON in step 3: CMake then downloads the official GSL 2.8 release from ftp.gnu.org, checks its SHA-256 checksum and builds it (needs a C compiler and make). For offline builds, point -DXTHERMO_GSL_ARCHIVE=<path to gsl-2.8.tar.gz> to a local copy of the same archive.

    2. Developer environment (optional)

    The tools used for development (documentation, verification) come from a conda + poetry environment: - conda (environment.yaml) creates the environment py313_xthermo with Python 3.13 and poetry; - poetry (pyproject.toml, poetry.lock) installs the Python packages at pinned versions.

    conda env create -f environment.yaml   # once
conda activate py313_xthermo
poetry install

    3. Build and install xThermo

    From the repository root, with the environment active:

    cmake -S . -B build -DCMAKE_INSTALL_PREFIX=install
cmake --build build -j
cmake --install build

    The build type is Release unless -DCMAKE_BUILD_TYPE is given. Options:

    Option Default Description
    XTHERMO_PYTHON ON Build the Python modules (SWIG)
    XTHERMO_BUNDLED_GSL OFF Build the pinned GSL release from source instead of using the system GSL
    XTHERMO_OPENMP OFF Use OpenMP for batch and lookup-table evaluation
    BUILD_SHARED_LIBS OFF Build the C++ library as a shared library
    XTHERMO_BUILD_TESTS OFF Build the developer test programs (ctest)

    cmake --install creates:

    install/
├── bin/xThermal                 # command-line tool
├── include/xThermo/             # C++ headers
├── lib/libxThermal.a            # C++ library
├── lib/cmake/xThermo/           # CMake package: find_package(xThermo)
└── API/python/cp3.13/           # Python modules; the name follows the Python version used by CMake
    ├── xthermo/                 # __init__.py, H2O.py, NaCl.py, H2ONaCl.py, _H2O.so, _NaCl.so, _H2ONaCl.so, ...
    └── xThermal/                # compatibility name

    To use these modules without pip, set PYTHONPATH=<path_to_repo>/install/API/python/cp3.13 (or PYTHONPATH=<path_to_repo>/build/python for the build tree).

    4. Set the install path (C++ use)

    Export the install directory so that CMake (find_package(xThermo)) finds the installed package (see the C++ API overview):

    export xThermo_DIR=<path_to_repo>/install

    Troubleshooting

    • ModuleNotFoundError: No module named 'xthermo': run pip install . in the environment you use, or set PYTHONPATH to the cp3.XX directory that matches your Python version.
    • SWIG or Python version changed (e.g. after brew upgrade): delete build/CMakeCache.txt, then configure and build again.
    • GSL was not found: install GSL (step 1), pass -DGSL_ROOT_DIR=<prefix>, or use -DXTHERMO_BUNDLED_GSL=ON.
